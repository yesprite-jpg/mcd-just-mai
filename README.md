# 说麦就麦 · 状态 × 习惯 × 约束 同解

> 麦当劳程序员创意开发大赛参赛作品。由个人独立开发，非麦当劳官方产品。

点麦当劳最花时间的不是付款，是**想吃什么**。而且"想吃什么"从来不是一件事：

- **当次状态**：今天想来点甜的 / 想过瘾 / 想清爽 / 没什么胃口 / 口重了想淡一点。
- **个人习惯**：我有固定那一顿，别给我换掉。跟以前港式茶餐厅点 A 餐 B 餐一样，不是别的不好吃，是吃习惯了，不用思考。
- **硬约束**：这次别超多少卡、预算就这些。

还有两件事你通常不会说出口，但决定了它该回你几句：**这顿你能花多少分钟**，和**你有多饿**。这两样**由系统推断**（当前时刻与星期、你的取餐方式、你过去点单的时刻），**永远不问你**。

现有的做法基本只解其中一件：一句话复购，或者按热量推荐。把明说的三件事当联立方程解、再把推断出来的两件事用来决定**给几个答案**的很少 —— 这个定位是逐仓库实读竞品后台账压出来的，不是自封的第一。

## 第一幕就是这个场景

开完会，只剩几分钟吃饭，你连想都不想：

```
我在开会，随便弄一个，别破坏我的老规矩
```

它算好券、算好价钱，回你**一个答案**，不多话、不反问、不让你挑。这就是全部交互。

同一句"随便弄一个"发生在周末晚上，它会给你**三张盖着的牌**让你翻，**翻到哪张才给哪张算价** —— 三张都合你今天的口味，其中一张是**最近没见你点过这个**。

## 它怎么决定给几个

| 时间 | 饿 | 你看到什么 |
|---|---|---|
| 紧 | 只是垫一口 | **一件拿着就走的**：从你的随手池按天轮换 —— 同一天问几遍都是它，明天自然换 |
| 紧 | 饿得狠 | **主食 ＋ 一件配品**：只从你的主食池按天轮换取主食，再配一口喝的；小食不许单独成一顿 |
| 宽 | 只是垫一口 | **三张牌，先盖住**：两张稳的 ＋ 一张生面孔，至少两张含主食；**翻哪张才算哪张的价** |
| 宽 | 饿得狠 | **一到两个扛得住的**：优先官方两件套／随心配这类组合；饿的人不该被要求挑，也不让他翻牌 |

这些格子是它内部的裁决表，**你永远不会在输出里看到格子名**，也不会看到"因为你赶时间所以……"这类解释。判断错了你只说一句话就能翻回来（"我不赶""今晚慢慢吃"），它不道歉、不复述。

推不出来时**默认按"赶"处理**：把一个有空的人判成赶，他只是少翻一张牌；把一个赶的人判成有空，他在开会时收到三张牌 —— 那正好毁掉这个工具的意义。

连着一周同一句"赶紧吃一点"，它也不会天天给你同一件：**它按今天几号，从你的常点清单里取第几样** —— 一天之内问几遍都是同一道，跨过零点自然换下一道，靠的是日期不是记性。清单只认真吃过的（测试建了又取消的单不算），一顿只算一票，套餐和它的子项不重复计票。但你当场点名要哪样（"别破坏我的老规矩"），就永远给你那一样，它不擅自换，也不提醒你吃过几回。

## 冲突时怎么排

自上而下覆盖：

| 顺位 | 依据 | 用来做什么 |
|---|---|---|
| 1 | 你当场明确说的（"我就要双层吉士"） | 压过一切，不评价、不提分歧 |
| 2 | 硬约束（热量额度／预算上限） | **筛掉**不合格候选，不参与打分 |
| 3 | 当次状态（甜／过瘾／清爽／口重…） | 在合格集合内**排序** |
| 4 | 个人习惯（最近 10 单 ＋ 你自述的老规矩） | 排序加分与"接近熟悉度"，**绝不当裁判** |

## 实际输出长这样

**赶的时候（一个答案）：**

```
双层吉士汉堡
   官方数值：能量 429｜蛋白 27｜脂肪 22｜碳水 31｜钠 1017
   券后应付：<金额> 元

下一步：在麦当劳 App／小程序里确认并付款
```

**不赶的时候（三张先盖住，翻到哪张算哪张）：**

```
三张选好了，先不告诉你都是什么。说"翻"我给第一张；不想吃就说"换"。

   第一张：偏甜
   第二张：不甜也不淡
   第三张：最近没见你点过的路数

翻。

草莓新地
   为什么合今天这一句：额度内最贴甜口（碳水 43／钠 84）
   官方数值：能量 245｜蛋白 4｜脂肪 6｜碳水 43｜钠 84
   券后应付：<金额> 元

这个不想吃。

可乐中杯
   为什么合今天这一句：同样过"想吃甜"的线（碳水 36），也是你老规矩里那一瓶
   官方数值：能量 147｜蛋白 0｜脂肪 0｜碳水 36｜钠 0
   券后应付：<金额> 元

就这个。

下一步：在麦当劳 App／小程序里确认并付款
```


营养数值取自麦当劳官方营养表实测读数；金额一律留占位符，实跑时由 `calculate-price` 现算 —— 本仓库不放真实订单个案。

**"盖住"只发生在位置与揭示次序上，选品从来不随机。** 三张都必须同时过三道门：这次的额度与预算、你当天那句话的口味、你熟的那一族 —— 缺一道就不许进池，宁可只给两张。翻开的位置不按熟悉度排，线索里也不透露哪张是生面孔。全部拒掉时它只把范围往相邻一族扩一次、再给两张；还不满意就直接拍一个最稳的给你，不补第四第五张，也不反问你到底想吃什么。生面孔那张的入选理由是"你最近没点过"，不是"官方刚上新"。

## 券这件事的真实边界

自动挑券能跑通，但**只认试算、不认券包**，四条限制如实讲：

- **不能凭"我的券包"下结论。** 券包接口官方自述不做门店与渠道校验，也不给商品字段。能不能减，得看这家店当前可用的券，再实算一次。
- **不拿原价当省钱基准。** 不带券时服务端已经自动降过一次价；拿原价比等于把平台的降价算成券的功劳，虚报给你。
- **判据只有一条**：同一家店、同一组商品，带券算出的应付低于不带券算出的应付，差额才是这张券为这一单省的钱。一张候选券＝一次算价。
- **会有"本店暂无可用券"**：这是门店维度的真实现象，不是故障。这时直接给应付价，不道歉、不硬凑。
- **满减门槛读不到**：门槛型规则只在企业团餐场景返回。所以它不说"我帮你看完了所有满减"，只说这一单实测省了多少。

## 安装

### 1. 申请麦当劳 MCP Token

去 https://open.mcd.cn/mcp → 右上角【登录】（手机验证码）→ 右上角变成【控制台】→ 点【激活】→ 同意服务协议 → 复制 Token。全程免费。

### 2. 把这段配置交给你的 AI 助手

**WorkBuddy**：左侧栏【专家·技能·连接器】→【连接器】页签 → 右上【自定义连接器】→【配置MCP】→ 粘贴下面内容 → 把 `YOUR_MCP_TOKEN` 换成真实 Token → 保存 → 回到【自定义连接器】把 `mcd-mcp` **启用**。

其他客户端（Cursor / Cherry Studio / Trae / Kiro / VSCode）用同一个 JSON，位置不同，官方各家教程见文末链接。

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": { "Authorization": "Bearer YOUR_MCP_TOKEN" }
    }
  }
}
```

### 3. 把 `SKILL.md` 贴进对话

第一次对话时对助手说：

> 请按 `SKILL.md` 的规则工作。我的老规矩是：双层吉士汉堡 + 中可乐。

这句话**说一次就够**。之后每次只需要说你那一句处境话。不设开场问卷 —— Token 绑的就是你自己的账户，装好就能读到你自己的历史。

## 数据边界与隐私（这段必须讲清）

它读的是**你私人消费记录**，所以把边界写死在这里：

- 只用**你自己账户**里麦当劳官方返回的**最近 10 单**，用来推你的老规矩、判"最近没点过"、估你惯常的点单时刻。
- **不保存、不上传、不发给第三方**：本作品没有服务端、没有数据库、不写任何文件；除麦当劳官方 MCP 之外不连任何地址。所有调用发生在你自己的 Token 与官方服务之间。
- 历史订单只回 10 单、没有翻页，所以它对"你没吃过"这种话**没有资格**；正文与输出里都禁止这类断言。
- 外送地址、收件人这类敏感数据，它**仅在「地址确认」这一步读取并展示给你本人点击确认**，不另存、不上传；确认后即随订单提交，不用于其它用途。
- Token 只放在你自己的环境变量里；仓库里只有 `${MCD_MCP_TOKEN}` 占位符。
- 所有订单、券、门店查询都发生在你自己账号与麦当劳官方服务之间；本作品不含服务端，不收集、不上传任何数据。
- 速率上限：每个 Token 每分钟 600 次请求，超出返回 429。一次完整求解最坏 15 次调用（含逐张试算券，见 `MCP_INTEGRATION.md` 调用预算），约占配额 2.5%；常见路径 6 次以内。

## 它不做的事（重要）

- **已在流程内自动下单。** 选好券、算好价后，先以可点击卡片问「取件方式」、再以可点击卡片确认「地址」，这两步是流程里唯二**必须停下等你点击**的地方，提速也不省；**没点就不会建单**。两步点完即自动走 `create-order` 建单返回支付链接，**付钱那一下始终由你自己按，它绝不自动扣款、也绝不调 `cancel-order`**。
- **不自动领券。** `auto-bind-coupons` 会改动你账户里的券（领了就有有效期），默认不启用；要用需要你明确同意。
- **不给健康建议。** 只报官方营养数值与口感描述，不评价某顿饭"好不好"。参赛声明写明"项目输出仅供参考，不构成医疗、营养或其他专业建议"。所以这条轴叫**体感**，不叫健康度。
- **不问你有没有时间、饿不饿、想不想花心思。** 这三样全部推断；默认零追问。唯一会问的一次是：历史订单为空时问一句你平时点哪几样，问过就记住。
- **不给人贴标签。** 没有"白领套餐""加班族吃什么"这类东西，也不出现任何职业或群体名。时间只从处境推断。
- **不赌。** 盖牌是呈现，不是抽奖：不出现概率、抽、隐藏款这类说法，也不碰儿童餐与周边玩具。
- **不追问第二次、不写解释性小字。** 不做问卷，不播报判断过程。
- **不自创标准。** 口感阈值全部用实测校准过的几条（见 `MCP_INTEGRATION.md` 实测记录），能量优先跟官方「500大卡套餐」分类走。

## 目标用户

- 每周点两三次麦当劳、每次都要花十几秒想"今天吃什么"的人。
- 有固定那一顿、但懒得在 App 里翻券的人。
- 时间被切成碎片、吃饭只有几分钟的人 —— 这种人最不需要第三个选项。
- 一边在意热量额度、一边又不肯放弃口感的人：这两件事在传统推荐里只能选一个。
